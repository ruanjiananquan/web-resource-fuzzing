## 提取口径

1. **三类来源分别对应三类证据**：路径片段（`href` 里的目录/文件名）、脚本文件名（`<head>` 里 `script`/`link` 的路径）、页面文字（标题、链接文字、正文）。同一词命中多类时在表里全部列出，供 D 判优先级。
2. **拼写照抄、大小写分两种处理**：`MockTerminal`（脚本目录名）和 `subdmain`（页面本身缺一个 o）一律原样保留；取自页面文字的 `Discovery`、`Enumeration` 在 `seeds.txt` 里按 URL 惯例写成小写 `discovery`、`enumeration`，原始大小写在来源表"页面原文"列逐字可查，没有改写页面本身。正确拼写 `subdomain` 的扩展留给 C 阶段显式声明，B 不擅自改写。
3. **不做同义词/词形发散**：单复数、`api/`、扩展名等一律交给 C 的规则，B 只交页面里真实出现过的词，避免把"猜的"混进"看到的"。
4. **数量**：18 个，落在 10–20 区间。宁可少交，不凭空补词。
5. **已删的无意义词**：虚词与介词、站名/工具名（FFUF、ffuf.me）、状态码（404）、泛化词（content、status、mining）、通用静态资源名（style、script）、扩展名（html/php/css/js）。理由逐条记在表2。
6. **边界**：`/cd/rate`（Rate Limited）属限速练习，按统一规范整条排除，其片段 `rate`、`limited` 也不入候选；但它仍在公开路径清单里登记，避免 E 核验时把它当成新发现。
7. **路径登记口径**：静态资源在首页源码里写作相对路径（`href="style.css"`、`src="MockTerminal/script.js"`），`公开路径清单.xlsx` 的"路径"列按浏览器解析后的绝对路径登记（`/style.css`、`/MockTerminal/script.js`），"页面中的位置"列保留源码原文，两边可对得上。

## 交接要点

- 给 C：`seeds.txt` + 来源表（`来源类别` 列决定"是否扩展"的初始权重）。
- 给 D：来源表的类别列直接对应 D 的四级优先级——路径片段原词 = 第 1 级，页面文字原词 = 第 2 级，规则扩展 = 第 3 级，通用字典项 = 第 4 级。
- 给 E：`公开路径清单.xlsx`。清单里的路径 ffuf 命中也不算新发现，须单列统计。

## 需要注意的局限（答辩要讲）

1. **来源单一**：只有一个首页，样本量小，18 个词是全站可见文字的近乎全部；这说明方法在小站上可行，不代表真实站点也只需读一个页面。
2. **人工提取、无爬虫**：可追溯但不可规模化，真实站点要靠多页采集 + 去噪，本周不做。
3. **教学靶场偏差**：ffufme 的目录名刻意贴近练习内容（`no404`、`param`、`pipes` 直接写在路径里），命中率天然偏高，不能据此推断排序优化的通用效果。
4. **提取词 ≠ 发现资源**：本阶段没有发出任何请求，`seeds.txt` 里的词能否成为可访问路径，要等 D 的试跑去验证，也可能大量落空。
5. **版本依赖**：截图与词表基于 A 的首页 HTML；若 A 后续更换靶场版本或端口（8080 → 18080），需同步更新来源表和截图编号。
6. **截图性质**：三张图是对 `素材/homepage.html` 的标注渲染（先按原 HTML 渲染，再加编号/高亮），不是带地址栏的浏览器截图——B 不跑靶场、不发请求，页面内容与 A 的 `http://127.0.0.1:8080/` 首页等价；若验收时要求带地址栏的实拍图，可等 A 的环境起来后换一张。

## 复核方式

**一键自检（推荐）**：在本目录运行 `python 证据自检.py`，脚本会把 `seeds.txt` 的 18 个词、来源表里 17 条 HTML 引文、清单里 18 条路径逐条回查首页 HTML，结果写进 `证据自检报告.txt`（当前 52 项全部命中）。组长或 E 想抽查时，跑一次就知道有没有编造。

**手工抽查**：打开 `公开路径清单.xlsx` 任意一条 → 在 `素材/homepage.html` 里搜 `href="..."` 或 `src="..."` → 命中即说明该路径确由页面公开（静态资源是相对路径，按首页 URL 解析即可）；目标词同法可在 `词语来源表.xlsx` 的 `页面原文` 列逐条比对。
